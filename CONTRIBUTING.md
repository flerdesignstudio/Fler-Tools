# Contributing to Graphic-Tools

First off, thank you for considering contributing to Graphic-Tools! It's people like you that make this an amazing open-source project.

## Code of Conduct

By participating in this project, you are expected to uphold our community and behavioral expectations:
- Be respectful and welcoming to all contributors.
- Provide and accept constructive feedback gracefully.
- Harassment or unacceptable behavior will not be tolerated.

## How Can I Contribute?

### Reporting Bugs

Before creating a bug report, please check the [existing issues](https://github.com/flerdesignstudio/Graphic-Tools/issues) to see if it has already been reported. When creating a bug report, please include as many details as possible:
- Use a clear and descriptive title.
- Describe the exact steps which reproduce the problem.
- Provide specific examples or screenshots if possible.
- Describe the behavior you observed and what you expected to happen instead.

### Suggesting Enhancements

Enhancement suggestions are also tracked via [GitHub issues](https://github.com/flerdesignstudio/Graphic-Tools/issues). When you create an enhancement suggestion:
- Use a clear and descriptive title.
- Provide a step-by-step description of the suggested enhancement.
- Explain why this enhancement would be useful to the users of Graphic-Tools.

### Pull Requests

Follow these steps to have your contribution considered by the maintainers:
1. Fork the repository and create your feature branch from `main`.
2. If you are adding a new graphic tool, ensure it follows the structure outlined in the [ARCHITECTURE.md](./ARCHITECTURE.md) documentation.
3. Ensure your code follows the existing style (Vanilla JS, lightweight CSS, no heavy frameworks).
4. Test your changes locally by running `npm run dev` and verifying everything works as expected.
5. Create a Pull Request with a clear title and a detailed description of your changes.
